Positioning & States

1. What is it?

Positioning classes (tw-relative, tw-absolute, tw-fixed) control element layouts. State modifiers (hover:, focus:, active:) apply styles only when elements are hovered, focused, or clicked.

2. Why is it important?

Interactive elements need feedback. Hover classes darken buttons, and focus classes highlight active inputs.

3. Syntax & Basic Example

<button class="tw-bg-indigo-600 hover:tw-bg-indigo-700 focus:tw-outline-none focus:tw-ring-2 focus:tw-ring-indigo-500">
  Submit
</button>

Basic description: Changing background on hover: `hover:tw-bg-blue-600`.

4. Code & Interactive Rendered Output

tailwind live sandbox
<div class="tw-p-2 bg-white rounded border">
    <input type="text" placeholder="Focus me..." class="tw-w-full tw-border tw-border-slate-300 tw-p-2 tw-rounded focus:tw-outline-none focus:tw-border-indigo-500 focus:tw-ring-1 focus:tw-ring-indigo-500">
</div>
Live Output & Execution Preview

Expected Layout / Behavior: A text field that displays an indigo border and a focus glow ring when clicked or tabbed.

5. Line-by-Line Explanation

  • focus:tw-border-indigo-500: Changes border color when focused.
  • focus:tw-ring-1: Adds a light ring outline when focused, boosting accessibility.
  • focus:tw-outline-none: Removes default browser focus outline, allowing you to use custom styles.

6. Key Properties, Methods & Syntax

Property / Method / Tag Description
hover:* Applies styles when the user hovers over the element with the mouse.
focus:* Applies styles when the element receives keyboard focus.
active:* Applies styles when the element is clicked.

7. Real-World Use

Dashboard notifications display count badges positioned absolutely at the top-right corner of card icons, and form fields highlight borders when focused.

Best Practices

  • Always include focus states alongside hover states to ensure keyboard accessibility.
  • Use transitions to smooth out state color changes.

Common Mistakes

  • Omitting focus styles when using focus:tw-outline-none, which makes the element inaccessible to keyboard users.
  • Using state prefixes on non-interactive elements (like paragraphs or divs), where hover effects carry no functional benefit.

9. Tech Screening Question

Q: How do focus state utilities improve web accessibility?
Answer:

When a user navigates a page using the Tab key on their keyboard, focus state utilities (like focus:tw-ring-2) highlight the active element visually. Without focus styles (or if you hide them using focus:tw-outline-none without an alternative), keyboard users cannot see which element is active, making the site unusable.

Explanation:

Highlighting focused elements is a core requirement of the WCAG accessibility guidelines.

focus:tw-outline-none focus:tw-ring-2 focus:tw-ring-indigo-500

10. Quick Revision

Use positioning classes (tw-relative, tw-absolute) to position elements on the screen. Add interactive feedback using state variants (hover:, focus:, active:).
